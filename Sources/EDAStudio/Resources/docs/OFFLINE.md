# 离线范围与资源闭包

## v0.1 实际行为

应用和 CLI 没有网络客户端。项目、采购 BOM、点对点线束、快照、计算器、引擎调用使用本地文件；新建示例的符号和封装随包。准备好的 KiCad 可在本地编辑/查看/仿真，仿真所用模型也必须本地存在。

联网阶段只有显式动作：克隆/推送 GitHub、下载引擎、安装工具链或主动获取器件资料。`fetch-engine.sh` 从官方 GitHub release 下载 10.0.6 并校验固定 SHA-256；该脚本不是应用自动运行的一部分。

## 离线准备清单

1. 工作台 app/CLI、完整 KiCad 文件夹和版本清单。
2. 符号库、封装库、3D STEP/WRL、SPICE 子电路/模型、资料 PDF。
3. 项目本地 fp-lib-table/sym-lib-table 与正确 `${KIPRJMOD}` 路径。
4. 所有自定义环境变量、场求解器和机械工具（如果项目使用）。
5. 供应链快照的来源、导入时间、币种/报价单位和替代料批准记录。

复杂外部资源当前不会被 snapshot 自动抓取。快照禁止跟随符号链接，确保不会悄悄复制工作目录以外内容。若项目依赖全局库或绝对模型路径，搬到另一台 Mac 可能缺库；必须手工形成闭包或等待 P2 的依赖锁功能。

## 目标闭包格式（P2）

`eda-lock.json`: 引擎版本和哈希、每个符号/封装/三维/SPICE 资源的来源/许可证/相对路径/哈希、变量展开结果、工作台版本、规则哈希。依赖图递归解析 SPICE `.include` 与三维替代模型，检测循环和未解析变量。索引只能引用锁定资源，缺项列成错误清单。

导出离线包前复制全部资源到 content-addressed `resources/sha256/`，重写仅允许的引用时产生可审查补丁并保留原文件。不能静默更换封装/模型。在清洁用户账户、隔离网络的 Mac 打开、编辑、检查、仿真和制造，并比对黄金数据；这才算完整工程闭包验收。
