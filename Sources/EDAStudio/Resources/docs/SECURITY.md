# 安全与工程数据保全

工作台只处理本地文件并调用显式选择的 KiCad 引擎。它没有联网客户端、账号、遥测、监听端口或自动插件安装。GitHub 和引擎下载由用户授权的外部工具/脚本完成。

## 已落实

- 路径拒绝绝对路径、`..` 和解析后的根外符号链接；快照拒绝符号链接，不悄悄收集外部目录。
- 元数据原子写；新建项目拒绝覆盖已有目录。
- 子进程参数数组，不通过 shell 解释项目名称或路径。
- 进程 stdout/stderr 文件捕获，不会因管道满挂死；超时有 terminate/kill。
- S-expression 预览限制 32 MB、128 层嵌套，错误显式报告。
- CSV 保护常见公式前缀，引号/换行正确转义。
- 制造任务冻结并校验源，失败不会移动为 release；检查退出码和报告内容双重验证。
- 下载引擎固定版本与 SHA-256，不使用未验证的“最新”重定向。

## 已知限制

本地文件权限来自操作系统；ad-hoc 签名不等于可信分发签名。GUI 选择任意二进制时用户需要信任该路径，当前没有验证引擎 Code Signing 身份。项目扫描不是敌对大文件沙箱；单进程库/BOM 编辑缺多写者锁。已禁用的 KiCad 规则不自动恢复，报告列明 ignored_checks。当前插件、离线审阅身份签名、完整 SBOM 和供应链防护尚未实现。

遇到不可信导入数据应保留原件，在副本执行，绝不把导入成功视为电气正确。未来引入几何/求解器和第三方插件时，需要单独进程、资源限制、声明权限、日志与结果 schema 验证。

严重错误包括项目覆盖/数据损坏、开短路遗漏、单位错位、漏铜层、BOM/变体与制造输出不一致。这类错误优先于 UI 与覆盖率目标，并阻止产品达标发布。
